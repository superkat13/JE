# Sage 1.25.0 self-repair threat review

| Threat | Control | Residual risk |
| --- | --- | --- |
| Voice command executes arbitrary code | Voice routes only to fixed Java actions; packet schema requires an empty `arbitrary_commands` array | Speech could open the review screen, but cannot export without a tap |
| Secret or token disclosure | Regex sanitization covers keys, tokens, passwords, Authorization/Bearer values, and common token prefixes | Unknown secret formats may require future sanitizer expansion |
| False authority claims | Capability states are read from Android APIs/settings; Available and Needs setup are distinct from Active | OEM settings may expose roles differently |
| Silent permission escalation | Sage only opens Android settings; no protected permission is granted programmatically | Owner can still grant authority manually |
| Device-owner abuse | No automatic provisioning; non-owner state is reported Unsupported | A separately provisioned device-owner installation remains powerful by Android design |
| Silent repair/export | Draft stays in private cache; share sheet opens only after explicit approval | Other apps selected by the owner receive the exported ZIP |
| Malicious repair packet | Fixed repository/branch/package/version, enum classifications, size limits, operation allowlist, no command field | Human review is still required for any later source change |
| Workflow command injection | JSON is parsed as data; no packet value is executed; branch name is generated by workflow | GitHub runner and third-party actions remain supply-chain dependencies |
| Automatic merge/release/install | Workflow has read-only contents permission and artifact-only output | Repository administrators can separately perform privileged actions |
| Signing-key exposure | Keystore remains the existing repository-controlled workflow input; bundle includes only certificate digest | Debug-style permanent key handling remains a repository governance concern |
| Unrelated file modification | Repair operation vocabulary is Sage-specific; workflow applies the deterministic release chain only | A future patch-producing pipeline needs explicit path enforcement |
| Data retention | Repair draft lives in app cache and contains sanitized logs | Android may retain cache until storage pressure or app cleanup |

## Security invariants

- Owner approval is required before export and installation.
- Availability is never reported as active authority.
- Repair packets cannot contain commands.
- Workflow artifacts are candidates, not releases.
- No workflow step pushes, merges, releases, or installs.
