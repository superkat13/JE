Prefix-loss fix (round 3, physical-tablet evidence: comment #6103106133, trial #3 recognized only the final syllables of the typed phrase):
- Root cause A (dominant): the owner was told to speak before the microphone was actually open. `VoiceRepairResponder.startWithTypedPhrase` returned "Microphone test started. Say … now" synchronously, while the recognizer is not created until remote-wake-stop acknowledgement + `ensureRecognizer` + `startListening` (~0.8 s). `onReadyForSpeech` was only a diagnostic log line, never surfaced.
- Root cause B: the local sherpa service unconditionally discarded the first `WAKE_TAIL_DISCARD_CHUNKS` (4, ~400 ms) for every turn, including a diagnostic capture that begins on an already-idle microphone, dropping the true phrase onset.
- Fix A (truthful readiness): `VoiceDiagnosticPort.capture` now takes `ready`/`speechBegan` callbacks; `AndroidSpeechPort.DiagnosticRecognitionListener` surfaces `onReadyForSpeech`/`onBeginningOfSpeech`; `VoiceRepairOrchestrator` stamps redacted `ready`/`speech_began` steps (scoped to the current capture so a retest re-prompts), fires a one-shot `onReady` callback, and adds a bounded `readyTimeoutMs` (15 s) with a new `VoiceRepairCause.READY_TIMEOUT` that refuses honestly instead of telling the owner to speak. New `VoiceRepairReadinessPresenter` + `VoiceRepairReadinessNotifier` persist the "microphone is listening now, please say …" prompt as exactly one SAGE/SYSTEM turnId-0 entry before notifying the UI (so it survives background→foreground), deduped per ready stamp. The immediate reply no longer says "now"; the honest readiness prompt is the only "speak now".
- Fix B (no onset loss in diagnostic mode): `SageSpeechIntents.EXTRA_DIAGNOSTIC_CAPTURE` marks the diagnostic recognizer intent; `SageSherpaRecognitionService.onStartListening` reads it into `CommandSpeechTurnState.diagnosticCapture`; `runRecognition` uses `state.tailDiscardChunks(WAKE_TAIL_DISCARD_CHUNKS)` → 0 for a diagnostic capture. Command turns keep the 4-chunk tail discard unchanged.
- `VoiceRepairReporter.traceStep` now appends redacted `ready_ms`/`speech_ms` latency (timestamps only, never audio/transcripts), and `READY_TIMEOUT` has an honest owner-facing failed report.
- Tests added/updated: `VoiceRepairReadinessTest` (6), `CommandSpeechTurnStateTest` (2), `VoiceRepairIntegrationTest` readiness battery (ready once, onset ordering, post-result ignored, retest re-prompt, cancel no-prompt, READY_TIMEOUT, overall deadline after readiness) with a multi-task due-ordered test clock; `VoiceDiagnosticAdapterTest` (Robolectric) marks the intent and surfaces readiness/onset, and its `TestScheduler` is now multi-task/due-ordered; `SageSherpaRecognitionServiceLifecycleTest` drives production `onStartListening` with the intent mark; `VoiceRepairResponderTest` asserts the new wording.
